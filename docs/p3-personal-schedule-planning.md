# 【本轮新增 P3】个人课表与短期项目规划

更新：2026-10-10。这是在现有 AgileCampus 上增加的校园功能，原 P0–P2 和已经接入的五项 P3 保留。学生导入自己的课表、考试或其他日程，再结合本人项目任务生成未来 7 天或 14 天的工作安排。

## 学生怎么用

1. 工作台点击「我的课表与日程」，也可从右上角账户菜单进入。
2. 上传 ICS 日历文件或 UTF-8 CSV，选择日期范围，检查预览，勾选需要的日程后确认。页面提供 CSV 模板；没有文件时可以手动添加一次日程、每周或隔周课程。
3. 设置可工作星期、开始／结束时间、每日最多投入分钟、每段工作最长时间和休息缓冲。默认工作日 18:00–22:00、每日最多 120 分钟、每段最长 45 分钟、缓冲 15 分钟。
4. 在项目的「AI 与草案」页面点击「结合课表规划我的工作」。选择分配给自己的任务，填写每项任务预计还需要多少分钟，选择起始日和 7／14 天。
5. 可以写本期目标，例如「本周完成登录接口并自测」。配置了项目原有 AI 服务后选择 AI 规划；也可明确选择规则规划。
6. 查看按天安排、每段对应任务、短期目标、排序理由及未排完的工作。确认后保存为本人安排；需要调整时选择「按新日程重新规划」。

## 【本轮新增】临时事件与重新规划

1. 突然有事时，在「我的课表与日程 → 补充临时事件」填写开始和结束时间。无需填写具体原因；本人备注可留空，显示为「临时安排」。单次最长 7 天，可修改或删除。
2. 保存后，日程页面列出需要重新核对的已确认计划。点击对应项目的「重新规划」，也可从原计划点击「按新日程重新规划」。
3. 页面带入原目标及仍可执行的任务。已完成、改派或阻塞的任务不会预选；本人重新核对剩余工时，不能把已过去的安排当成已经完成的工作。
4. 生成新草案会避开课表、临时事件和其他项目已确认安排。原安排继续保留；AI 失败、没有可安排时间或取消新草案都不会提前取消原安排。
5. 确认新草案时，事务中一起取消原安排并确认新安排。确认前又有日程／任务变化会拒绝旧草案；多个替换草案只有一个可以替换同一原安排。

## 【本轮新增】自愿共享模糊日程

- 默认为私有：旧课表、导入课表、新临时事件以及个人工作安排均不会自动公开。
- 第一步在「日程共享设置」选择哪些团队可查看；第二步在具体日程的修改表单勾选「允许向已选择的团队显示这次忙碌时间」。手工新增和临时事件表单也可以直接勾选。只选团队而未授权事件，仍不会显示该事件。
- 可额外勾选「同时显示已确认的项目工作时段为忙碌」。工作时段只共享给该项目所属且你已授权的团队，不包括草案、取消安排、任务名或目标。
- 团队页点击「忙碌日程」，组员、组长和老师看到相同的 7／14 天视图。时间按半小时向外取整，接壤或重叠片段合并，只显示「忙碌」。例如真实安排 18:07–19:03，公开为 18:00–19:30；具体名称和事情始终只对本人显示。
- 可以取消某一次日程的公开，也可以取消某个团队授权。刷新后即按当前授权读取；退出团队的人员不能继续读取或出现在共享名单中。
- 「未共享」和「没有公开忙碌时间」都不等于有空。安排团队会议前还需联系成员确认。共享入口需登录，不提供无需登录的个人日程链接。
- 只改共享设置或同一事件的公开选项，不改变可投入时间和已有计划的有效性。重复导入不会更改已有事件的公开选项。

例如：周一 18:00–20:00 上课，可工作时间为 18:00–22:00，缓冲 15 分钟，剩余登录任务 60 分钟。排程最早从 20:15 开始，根据每段上限拆分工作；课程占满可用时间时显示未排完工作，不编造空闲时间。

## 结合了哪些真实项目数据

| 数据 | 用途 |
|---|---|
| 项目主任务完成情况、阻塞情况 | 给出当前进度背景 |
| 本人未完成、未阻塞的任务 | 限定可以安排的真实工作 |
| 子任务和前置依赖 | 只选叶子任务；前置任务未完成的后续任务暂不排入 |
| 任务描述、验收标准、优先级 | AI 整理工作目标和排序理由 |
| 任务、阶段、迭代及项目截止日 | 采用其中最早的截止日约束安排 |
| 学生填写的预计剩余工时 | 计算工作量；完成率不能直接换算成还需多少小时 |
| 本人课表、日程和时间偏好 | 限制可投入时段 |
| 本人在其他项目确认的安排 | 防止跨项目撞时间，并合计每日投入上限 |

AI 负责提出目标、任务顺序和理由；服务端排程器负责时间计算与冲突检查。AI 不能发明任务、改派负责人或把任务自动标为完成。已经逾期的任务会明确提示，安排补救时间不表示原截止日已经满足。

## 导入格式

| 格式 | 第一版支持情况 |
|---|---|
| ICS | 一次日程、全天日程、按天／按周及隔周重复、EXDATE 例外日期、RECURRENCE-ID 调课；使用文件时区，无时区按北京时间 |
| CSV | `名称,开始,结束,重复周数,间隔周数`；也支持 `title,start,end,repeatWeeks,intervalWeeks`；时间为 `YYYY-MM-DD HH:mm` 或 `YYYY-MM-DDTHH:mm`，按北京时间 |
| 手动输入 | 一次日程／每周／隔周课程，最多 26 次；修改和删除针对单次课程 |
| Excel | 先另存为 UTF-8 CSV；暂不直接解析 XLSX |
| 截图／PDF | 本轮未做识别；可先手动录入或整理成 CSV |

重复周数表示生成几次课程，间隔周数为 1 或 2。例如 `软件工程,2026-10-12 18:00,2026-10-12 20:00,16,1` 是从该日起每周一次、共 16 次。模板里的示例日期需换成自己学期的日期。

文件上限约 500KB，同时限制 200,000 字符、500 个 ICS 事件定义及 1,000 次展开日程；单次导入日期范围最多 187 天。复杂重复规则、不认识的时区和无结束时间的事件会明确拒绝，避免把导入不完整误当成有空。日程列表每页 50 次。

同一人的名称、开始和结束完全相同的日程会去重；重复导入不清空旧课表。导入的是所选日期范围内的具体日程，不是自动同步订阅；教务系统发生调整后需要自行修改对应课程或重新核对导入。

## 隐私与确认

- 完整课表与个人安排按登录用户隔离。老师、组长和其他成员只能通过独立共享视图读取本人自愿授权的模糊时间，不能读取或修改他人的事件名称、备注、计划目标或明细。
- AI 获得项目任务、学生输入的目标／工时、可投入容量等信息；不发送课程名称、原始文件或私人日程明细。使用现有模型服务，任务内容仍会提供给该服务。
- 草案有效 24 小时。课表、时间偏好、任务或其他已确认安排变化后，旧草案不能直接确认，需要重新规划；已经开始的工作段也不能事后确认。
- 确认只保存个人安排，不创建团队迭代，不修改共享任务日期／状态，不写入共享聊天、通知或过程证据。
- 学生和管理员可以规划本人任务；教师角色不能生成／确认工作计划。退出项目无法再访问项目内计划，归档项目不允许新规划。
- 写入使用请求 UUID 和版本校验。同次重试不会重复导入、重复确认；旧版本修改会提示冲突。

## GitHub 开源模块调研与选择

| 项目 | 判断与本轮使用 |
|---|---|
| [node-ical](https://github.com/jens-maus/node-ical) | 已接入 0.27.3，Apache-2.0。适用于服务端 ICS 解析、重复规则和例外日程；在库能力外增加导入范围及规则限制。许可证见 [副本](licenses/node-ical-Apache-2.0.txt) |
| [PapaParse](https://github.com/mholt/PapaParse) | 已接入 5.7.0，MIT。解析带引号、逗号等内容的 CSV，避免自己用字符串拆分解析。许可证见 [副本](licenses/papaparse-MIT.txt) |
| [ical.js](https://github.com/kewisch/ical.js) | 可选替代方案，本轮未引入。与 node-ical 能力重叠，时区数据还需额外处理，不同时装两套解析器 |
| [FullCalendar](https://github.com/fullcalendar/fullcalendar) | 可在以后需要周视图拖动时考虑，本轮未引入。当前按天列表已能导入、核对和查看计划，先控制界面和依赖规模；部分高级插件另有许可 |

本轮没有搬入其他整套项目管理平台，也没有复用需要另起服务的自动排期系统。项目已有模型接入与任务权限直接复用，时间约束由小型纯函数处理。

## 部署与验收

新增迁移 `0013_personal_schedule_planning.sql`，四张表：`personal_schedule_state / personal_schedule_events / personal_schedule_requests / personal_work_plans`。有完整迁移账本的数据库执行 `npm run db:migrate`；无需新的服务、端口或 AI 密钥，沿用现有 DeepSeek 配置。Node.js 使用 22 或 24 及以上的受支持版本。

【本轮新增】`0014_emergency_availability.sql` 在上述表中增加团队授权、独立共享版本、事件公开选项和计划替换关系；不增加新服务或依赖。升级后所有旧日程保持私有。部署前备份，执行原迁移流程后检查「私人事件 → 自愿共享时间 → 老师查看 → 撤回 → 补充事件 → 重新规划 → 确认替换」。

专项测试覆盖导入／时区／单双周／例外日期、冲突排程、跨项目每日工时、去重与版本、权限、AI 错误输出、草案变化与确认。AI 单测使用模拟模型，不能代替真实模型调用。

浏览器脚本为 `scripts/verify-personal-schedule-browser.mjs`，只运行于本地站点和本地数据库，验证导入预览、增改删、生成／确认／取消、课表避让、私有数据与手机宽度。完整测试数字和实际结果见 [最新进度](team-progress-20261009.md)。真实学校导出的样本、真实学生体验、真实 AI 与阿里云公网部署仍需实际条件。
