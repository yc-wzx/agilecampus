# 唯笃队 P0–P2 补齐与交接

本轮在老师项目和已提交代码上增量补齐，沿用 [接口契约 v2.0](team-interface-contract.md) 的 32 项任务。团队展示主页仍在腾讯文档，应用网站计划部署阿里云。

## 新补的功能

| 功能 | 用户可以做什么 | 入口／服务 |
|---|---|---|
| 完整工作台 | 看本人任务、活跃迭代和待修改成果，分页进入具体事项 | `/dashboard`；`getMyWorkspaceSummary` |
| 教师多项目总览 | 看自己任教团队的任务、迭代、成果、活动和风险，可包含归档项目 | `/teacher`；`listTeacherProjectOverview` |
| 评论与 @ | 在任务侧栏发表评论、编辑自己的评论、删除；选择当前成员发通知，点击通知定位评论 | `@/lib/comment`；固定 Action 路径 `/projects/{id}/comments/actions` |
| 项目公告 | 教师／管理员发布、编辑、置顶替换、撤下、重新发布；学生只读，概览显示置顶内容 | `/projects/{id}/announcements`；`@/lib/announcement` |
| 规则周报 | 按周看创建／完成／重开任务、正式成果提交／审核、下一轮计划和当前阻塞／逾期；下载 Markdown | `/projects/{id}/reports`；`@/lib/report` |
| 透明风险 | 查看逾期、长期阻塞、迭代临近结束且进度偏低、长期无活动四条提示 | `@/lib/risk`；概览和教师页显示阈值／来源／未知条件，不自动评分 |
| 统一过程证据 | 按成员、日期、里程碑、迭代和类型筛选，导出当前筛选的完整清单 | `/projects/{id}/evidence/process`；`@/lib/evidence` |
| AI 连续上下文 | 选择项目共享或本人个人会话、继续对话、分页看历史；有限消息与字符范围 | 原看板助手及 `/projects/{id}/ai-drafts`；`@/lib/agent/context` |
| AI 读取新增业务 | 在授权项目内读迭代、正式成果、反馈、复盘和统计 | `@/lib/agent/p0-p2-tools`；复用 C/D/E 服务 |
| AI 草案完整流程 | 任务池生成草案 → 调整名称／日期／候选任务 → 预览 → 确认创建计划迭代；也可取消 | `@/lib/agent/iteration-draft`；E 管理接 C 确认事务，只选已有任务，24 小时有效 |
| 到期／完成通知 | 到期扫描提醒未完成任务负责人，任务完成通知创建者，保留成果／指派／迭代通知 | `@/lib/notification-reminders`；受保护的 cron、业务条件去重 |
| 外部发送可靠性 | 配置并绑定飞书后发送；明确失败退避重试，成功记录；无法判断是否送达则停止自动重发 | `@/lib/external-notifications`；设置页显示渠道状态 |
| 部署与恢复 | 检查配置、发布、健康检查、备份、恢复到独立库、切换旧镜像 | `scripts/ops.mjs`、生产 Compose、Caddy、内部提醒调度 |

周报区分“本周事件”和“当前状态”，不依赖 AI。过程证据合并任务动态、评论、迭代结束、复盘、正式成果、审核和反馈；旧操作没有留痕就不补造，已删除评论的正文不导出。单次过程导出上限 5000 条，截断明确说明；原 D 成果证据页保留。

评论编辑有版本冲突处理；同一评论同一接收人只通知一次。公告同项目只能有一条置顶，编辑正文不重复通知，明确重发才重新通知。个人会话和草案仅本人可读，退组失去访问权限；共享上下文不加入他人个人聊天或私有成果草稿。

## 模块衔接

浏览器写操作从服务端会话取身份，不传任意 actorId。公共 DTO 保持在 `src/contracts/p0-p2.ts`，固定入口和 `Result<T>`／五种错误码沿用 v2.0；写入保留 requestId 幂等和版本校验。

- A 从 C/D/F 聚合工作台，从 C/D/E 聚合教师页；每项单独报告查询失败。
- B 的概览接 E 风险和 F 公告，新增周报／过程证据页；C 的侧栏挂 E 评论。
- E 的草案生成／编辑／取消复用 C 的预览确认，不另写迭代创建逻辑。确认前不改任务，确认后创建 planned 迭代。
- D 的正式成果 outbox 仍由一个组合消费者写 E 动态和 F 通知；周报／证据复用 D 的正式版本范围。
- F 的内部 reminders 调度成果事件、到期扫描和外部发送；密钥来自环境，不出现在宿主 cron 命令里。

成果写 Action 保留原接口和事务权限校验，成功后由页面发起一次完整刷新／新成果跳转，重新读取数据库。浏览器验收不靠手动刷新掩盖旧状态；冲突或失败保留输入供核对，不自动覆盖。

旧任务 CRUD、Agent API、原聊天返回字段和 `plan_sprint` 继续兼容。成果入口仍登记 PPT、视频、文档和仓库链接，没有加入文件网盘或视频转码系统。

## 数据与验证

新增迁移 `0010_comments_announcements` 和 `0011_scoped_ai_notification_delivery`，SQL／snapshot／journal 一起提交。生产只用 db:migrate；已有账本的 0007 旧库增量升级已验证。老师早期没有账本的数据库需先在副本核对基线，不能直接重放初始化迁移。连接默认 UTC，业务日按北京时间；历史无时区时间先抽查，不猜测批量修正。

本地真实 pg_dump／pg_restore 独立恢复验证：用户、团队、成员、项目、任务、成果、版本、反馈、评论、公告、会话、消息、草案、通知和发送队列共 15 张表内容一致，恢复后可写，重复迁移正常。最终自动化与页面验收数字见 [最新进度](team-progress-20261009.md)。

需要真实条件的事项不写成已完成：P2-07 同学试用按 [模板](usability-trial-template.md) 实际记录；P2-08 服务器未购买，Linux 容器／HTTPS／公网／镜像回退待目标环境；P1-11／P2-09 飞书真实送达和真实模型问答／生成待凭据。模拟模型及浏览器草案夹具不当作外部成功证据。

负责人本地 P3 试验没有混入本轮；P4 暂缓范围不扩张。部署步骤见 [阿里云方案](aliyun-deployment.md)。
